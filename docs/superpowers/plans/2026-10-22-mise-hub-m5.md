**Interfaces（后续 UI 任务按此实现）：**

```rust
// diagnostics.rs
pub struct Probe {
    pub name: &'static str,           // "registry" | "ls" | "config" | "env" | "tasks" | "outdated" | "ls-remote"
    pub ok: bool,
    pub network: bool,                // true 只有 ls-remote（联网探测）
    pub detail: Option<String>,       // 失败时的原始 stderr / 错误文本
}
pub struct DiagnosticsReport {
    pub program: PathBuf,
    pub version: Option<String>,      // `mise --version` 失败时为 None
    pub probes: Vec<Probe>,
}

// mise.rs additions
impl Mise {
    pub fn program(&self) -> &Path;   // 已定位的 mise 可执行文件路径
    pub fn diagnostics(&self) -> DiagnosticsReport;
}

// update.rs
pub struct UpdateManifest { pub version: String, pub page_url: Option<String> }
pub enum UpdateCheck {
    UpToDate,
    UpdateAvailable { latest: String, page_url: Option<String> },
}
pub fn parse_manifest(json: &str) -> Result<UpdateManifest, CoreError>;
pub fn is_newer(latest: &str, current: &str) -> bool;
/// 纯函数：给定 fetcher 返回的清单文本，判定更新状态（网络在 fetcher 里，判定逻辑可离线测试）。
pub fn check_update(fetcher: impl FnOnce() -> Result<String, CoreError>, current: &str)
    -> Result<UpdateCheck, CoreError>;
/// 阻塞 HTTP GET（只允许在后台线程调用）。非 2xx、超时、非法 JSON 都是 Err。
pub fn fetch_manifest(url: &str, timeout: std::time::Duration) -> Result<String, CoreError>;

// settings.rs 变更
pub struct AppSettings {
    pub theme: String,
    pub locale: String,
    #[serde(default)]                 // 旧 settings.json 缺此字段时为空 = 更新检查禁用
    pub update_manifest_url: String,
}
```

**规则：**

- `diagnostics()` 探测 App 依赖的 JSON 命令：`registry --json`、`ls --json`、`config ls --json`、`env --json-extended`、`tasks ls --json`、`outdated --json`（本地），`ls-remote node --json`（联网，`network: true`）。全部为只读命令；失败不 panic，原始 stderr 进 `detail`。
- `version()` 失败不阻塞探测：继续跑 probes，`version` 为 `None`。
- `is_newer`：剥前缀 `v`，按 `.` 切段取数字段逐段比较，段数不齐补 0；非数字段整体忽略（`0.2.0-rc.1` 按 `0.2.0` 比较）。`latest == current` → false。
- `fetch_manifest` 用 `ureq`，只在后台线程调用；请求超时由参数控制（UI 传 10s）。
- 测试全部离线：`is_newer` 表驱动；`parse_manifest` 合法/缺 page_url/非法 JSON；`check_update` 用假 fetcher（Ok/Err 两路）；diagnostics 用 RecordingRunner 断言每个探测的 argv（含 `-C` 缺席——诊断是全局只读）与失败注入；`AppSettings` 旧格式（缺字段）反序列化默认空 URL。

**Acceptance：** `cargo test -p mise-core` 全绿。

## M5-T2（UI）：设置 / 诊断页

**Files:** Create `crates/mise-hub/src/views/settings.rs`; modify `state.rs`, `app.rs`, `sidebar.rs`, `views/mod.rs`, locales（en.yml + zh-CN.yml 同步补键）。

- `Selection::Settings` 新增；侧边栏「工作台」底部加「设置」导航项。
- 页面分区：
  1. **外观**：主题下拉（`theme::theme_names`）、语言下拉（en / zh-CN），选择即应用并持久化（与头部选择器同逻辑，抽成可复用函数避免复制粘贴）。
  2. **mise 诊断**：可执行文件路径、版本、7 项能力探测的 OK / FAIL 徽标；FAIL 展开显示原始错误；「重新探测」按钮走后台线程 + `Loadable` 模式（UI 线程不阻塞）。
  3. **应用信息**：App 版本（`mise_core::version()`）、设置文件路径、项目清单路径（`store_path`）。
  4. **更新**：清单 URL 编辑（写入 `AppSettings.update_manifest_url`）；URL 为空时「检查更新」禁用并显示说明；检查走后台线程（`fetch_manifest`），结果三态：最新 / 有新版本（显示版本号 +「打开下载页」按钮，用平台 opener 打开浏览器）/ 失败（原始错误）。
- 平台 opener：`opener_command(url) -> (String, Vec<String>)` 纯函数（macOS `open`、Windows `cmd /C start`、Linux `xdg-open`）+ `open_url` 封装；测试断言三平台 argv 与 URL 原样传递。
- `state.rs` 增加 `diagnostics: Loadable<DiagnosticsReport>` 与 `update: Loadable<UpdateCheck>`（含 in-flight 去重），stale-guard 模式沿用现有页面。
- 所有文案走 `t!`，en / zh-CN 两份 locale 同步。

**Acceptance：** `cargo test --workspace` 全绿；`cargo run -p mise-hub` 人工过一遍设置页（GUI UNVERIFIED 项记录进验收文档）。

## M5-T4：打包分发 + CI + 文档

**Files:** Create `scripts/package-macos.sh`, `.github/workflows/release.yml`, `README.md`; modify 无（脚本/文档独立于 crate）。

- `scripts/package-macos.sh`：`cargo build --release` → 组装 `dist/mise-hub.app/Contents/{MacOS,Resources}`（Info.plist 版本从根 `Cargo.toml` 读取；无图标资源时留空 `CFBundleIconFile`）→ 可选 `--dmg` 用 `hdiutil` 打 dmg。不签名、不公证，脚本头部注释说明。

- `README.md`（英文为主、附中文简介）：项目定位、功能一览、从源码构建、macOS 打包步骤（含 Gatekeeper 右键打开说明）、CI 发布流程、更新清单 JSON 格式（`{"version": "...", "page_url": "..."}`）与如何配置 URL。

**Acceptance：** `bash scripts/package-macos.sh` 在本机产出可启动的 `dist/mise-hub.app`；workflow 语法用 `actionlint`（若本机可用）或人工审阅，标注 CI 实际运行 UNVERIFIED。

## 全局红线复核（每个任务提交前自查）

- mise 全部走 CLI 子进程；写配置只走 `use`/`set`/`unset`；诊断与更新检查绝不写任何文件（设置页写的是 App 自己的 `settings.json`，不是 mise 配置）。
- 不写死 macOS：opener、打包脚本之外的 Rust 代码一律 `cfg` 分支或纯函数。
- 新文案 en / zh-CN 同步；无「假装已实现」的按钮（更新 URL 留空时按钮禁用并说明原因）。
- UI 线程不做阻塞 IO：诊断探测与更新检查都走后台线程 + `Loadable`。
