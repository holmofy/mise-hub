```jsonc
// mise task info <name> --json → 同上，另加 cache / skip_if / usage_spec

  "JAVA_HOME": { "source": "", "tool": "java", "value": "/..." } }

// mise set（无参数）→ 文本表格，值可含空格：
// A  1     /proj/mise.toml
// B  x y z /proj/mise.toml
// 兜底：mise set <NAME> 只输出该变量的值
```

**信任：** 手工写入的 `mise.toml` 未信任时，`set` / `tasks` / `env` 会直接报错。GUI 必须检测并引导 `mise trust`，不能静默失败。

**已验证的 CLI 能力：**
- `mise upgrade [--dry-run] [--bump] [--global|--local] [--prune] [tool@ver]`
- `mise uninstall [--dry-run] [-a] [-y] [tool@ver]`
- `mise use [--dry-run] [--pin|--fuzzy] [--global] [tool@ver]`（dry-run 输出 `would install` / `would update <path> (add: node@20.11.0)`）
- `mise search <q> [--all] [--match-type fuzzy|contains|equal]`（纯文本表格）
- `mise trust <dir>`

### M2-T1（core，接口先行）：outdated / uninstall / upgrade / use / tool info / trust

**Files:** Create `crates/mise-core/src/outdated.rs`, `crates/mise-core/src/manage.rs`; modify `types.rs`, `mise.rs`, `lib.rs`.

**Interfaces（后续 UI 任务按此实现）：**

```rust
// outdated.rs
pub struct OutdatedTool {
    pub name: String,
    pub requested: Option<String>,
    pub current: Option<String>,
    pub latest: Option<String>,
    pub source_path: Option<PathBuf>,
}
pub fn parse_outdated(json: &str) -> Result<Vec<OutdatedTool>, CoreError>;

// types.rs (tool info)
pub struct ToolInfo {
    pub backend: String,
    pub description: Option<String>,
    pub url: Option<String>,
    pub installed_versions: Vec<String>,
    pub requested_versions: Option<Vec<String>>,
    pub active_versions: Option<Vec<String>>,
    pub config_source: Option<String>,
}

// manage.rs
pub struct UsePreview { pub install: Vec<String>, pub config_updates: Vec<PathBuf>, pub raw: String }
pub fn parse_use_dry_run(text: &str) -> Result<UsePreview, CoreError>;

// mise.rs additions
pub fn outdated(&self, project_root: Option<&Path>) -> Result<Vec<OutdatedTool>, CoreError>;
pub fn tool_info(&self, tool: &str, project_root: Option<&Path>) -> Result<ToolInfo, CoreError>;
pub fn upgrade_stream(&self, spec: Option<&str>, bump: bool, global: bool, project_root: Option<&Path>) -> Result<Receiver<StreamEvent>, CoreError>;
pub fn uninstall_stream(&self, spec: &str, project_root: Option<&Path>) -> Result<Receiver<StreamEvent>, CoreError>;
pub fn use_dry_run(&self, spec: &str, global: bool, project_root: Option<&Path>) -> Result<UsePreview, CoreError>;
pub fn use_apply_stream(&self, spec: &str, global: bool, pin: bool, project_root: Option<&Path>) -> Result<Receiver<StreamEvent>, CoreError>;
pub fn trust(&self, dir: &Path) -> Result<(), CoreError>;
```

**规则：**
- `upgrade` 不带 spec 时升级所有；带 spec 时只升级该工具。`--global` / `--local` 只在有项目时传 `--local`（全局范围用 `--global` 且不带 `-C`）。
- `uninstall` / `use` 的 spec 一律 `{tool}@{version}`，原样传递。
- `use_apply_stream` 只在用户确认预览之后调用；`--pin` 由 UI 选择。
- 所有写操作仍只走 mise 命令，核心层不碰 TOML。

**Tests：** outdated 解析（完整 / 缺 current / `current == latest` 不过滤——由 UI 决定）；`parse_use_dry_run`（would install / would update / 多行 / 空）；`upgrade_stream` 与 `uninstall_stream` 的 argv 断言（含 `-C` 顺序与 `--dry-run` 不出现）；`tool_info` 解析；`trust` 调用 argv。

**Acceptance：** `cargo test -p mise-core` 全绿。

## M3：环境变量

### M3-T1（core）：env 数据层

**Files:** Create `crates/mise-core/src/env.rs`; modify `mise.rs`, `lib.rs`.

```rust
pub struct EnvVar {
    pub name: String,
    pub value: String,
    pub source: Option<PathBuf>,   // 空 = 工具注入或系统
    pub tool: Option<String>,
}
pub struct EnvDeclaration {
    pub name: String,
    pub value: String,
    pub source: PathBuf,
}
pub fn parse_env_extended(json: &str) -> Result<Vec<EnvVar>, CoreError>;
pub fn parse_set_list(text: &str) -> Result<Vec<EnvDeclaration>, CoreError>;
pub fn path_segments(value: &str) -> Vec<String>;

// mise.rs
pub fn env_extended(&self, project_root: Option<&Path>) -> Result<Vec<EnvVar>, CoreError>;
pub fn env_declarations(&self, project_root: Option<&Path>) -> Result<Vec<EnvDeclaration>, CoreError>;
pub fn env_value(&self, name: &str, project_root: Option<&Path>) -> Result<String, CoreError>; // 兜底 mise set NAME
pub fn set_env_stream(&self, name: &str, value: &str, global: bool, project_root: Option<&Path>) -> Result<Receiver<StreamEvent>, CoreError>;
pub fn unset_env_stream(&self, name: &str, global: bool, project_root: Option<&Path>) -> Result<Receiver<StreamEvent>, CoreError>;
```

**规则：**
- `parse_set_list`：每行 `NAME  VALUE  SOURCE`；name 为第一个空白分隔 token；source 为最后一个以 `/`、`~` 或盘符开头的 token；中间为 value。解析不确定时（value 含与 source 相同形状的 token），UI 层对每个 name 调 `env_value` 兜底。
- 生效来源：`source` 非空即来自配置文件；`tool` 非空即工具注入；两者都空为系统/未知。
- `set_env_stream` 使用 `mise set NAME=VALUE`（`--global` 或 `-C`），`unset_env_stream` 使用 `mise unset NAME`。
- 敏感值：提供 `redact` 标记的读写能力（`mise set` 支持 `--redact`？若没有，则不实现标记，只在 UI 做显示/隐藏，并在报告说明）。**构建者需先核实 `mise set --help` 是否有 redact 相关 flag；没有就只做 UI 隐藏。**

**Tests：** env-extended 解析（有 source / 有 tool / 两者都空）；set-list 解析（值含空格、路径含空格的不确定行）；PATH 分段；写操作的 argv（`-C`、`--global`）；`set NAME` 兜底。

```rust
pub struct Task {
    pub name: String,
    pub aliases: Vec<String>,
    pub description: Option<String>,
    pub source: Option<PathBuf>,
    pub depends: Vec<String>,
    pub depends_post: Vec<String>,
    pub wait_for: Vec<String>,
    pub hide: bool,
    pub global: bool,
    pub run: Vec<String>,
    pub file: Option<PathBuf>,
}
pub struct TaskGraph { pub nodes: Vec<Task>, pub edges: Vec<(String, String)> }
pub fn parse_tasks(json: &str) -> Result<Vec<Task>, CoreError>;
pub fn build_graph(tasks: Vec<Task>) -> TaskGraph;
pub fn dependency_order(graph: &TaskGraph, task: &str) -> Vec<String>; // 拓扑序，缺失依赖原样保留

// mise.rs
pub fn tasks(&self, project_root: Option<&Path>) -> Result<Vec<Task>, CoreError>;
pub fn run_task_stream(&self, task: &str, project_root: Option<&Path>) -> Result<Receiver<StreamEvent>, CoreError>;
```

**Tests：** 解析（完整 / 缺 description / hide）；图构建；拓扑序；循环依赖不 panic；argv 断言。

## 全局验收标准（每个阶段结束）

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build --workspace
```

- 不写任何 `mise.toml`；写操作只走 `mise use` / `set` / `unset` / `uninstall` / `upgrade`。
- 所有 mise 调用带 `-C`（全局操作除外）。
- 破坏性操作（卸载、删变量、改配置）二次确认并展示影响范围。
- 文案走 `t!`，两个 locale 键集一致。
- 未信任配置有明确引导，不静默失败。
